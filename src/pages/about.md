# About

I write the docs, build the tools, and test the AI. I'm a software engineer turned content engineer who makes documentation work for both the people who read it and the AI assistants that answer from it.

At Nokia, I write and maintain documentation for SR Linux, a data center network operating system, and have led the release notes process across 10 to 15 releases. I also work on what happens after the docs are published: how AI assistants read them, and whether they give customers the right answer.

That work started with the AI assistant built into the SR Linux CLI. I partnered with another writer to prepare our security documentation for it, then tested its answers against the source. It pulled answers from the internet, described features the product never had, and dropped brackets from code samples. The lesson stuck with me: an AI is only as good as the content it reads, and it fails quietly. I later designed test scenarios for our Kapa.ai documentation chatbot, which led to a new response that routes out-of-scope questions to Nokia Services.


When something is missing from our workflow, I build it. I proposed and built an email-to-Jira feedback system now used across 14 products, created Cursor skills for release notes and glossary work (colleagues still use the release notes skills), and co-developed the version switcher in our WebHelp portal.

Two rules I carried over from engineering still shape how I work:

Test before you trust — I don't document a configuration until I've run it on a simulator, and I don't trust an AI answer until I've checked it against the source.

Build what's missing — the best fix is often a small tool or a clear standard that makes everyone's work easier, like the release notes standards I co-authored for SR Linux.

My background combines ten years of software engineering with more than eleven years of technical communication. I started out building and testing telecom and mobile software. Along the way, I wrote the design documents for our projects, and both my team and I noticed I had a knack for making complex products simple to understand. That's what led me into documentation full-time in 2015. Since then, I've reverse-engineered C and C++ code to document undocumented APIs, written conceptual content for auto-generated API references, and spoken at STC conferences on chatbots in content delivery (2018) and API documentation (2019).

I'm looking for content engineering roles where I can write the documentation and build the systems that make it work for people and AI. If that's the work you do, I'd love to connect.
